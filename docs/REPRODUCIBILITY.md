# Reproducibility

## Current status

The repository is **inspectable but not reproducible from a clean clone**. It contains the maintained source, archived notebooks, boundary geometry, a privacy-reviewed thesis, focused tests, and selected historical outputs. It does not contain the exact registry snapshot, processed station data, trained models, routing cache, GraphML networks, seeds, or run manifests required to reconstruct the submitted experiments.

This statement describes the repository as it exists after the 2026 portfolio work. It does not certify the thesis results and does not imply that the pipeline was rerun.

| Capability | Clean-clone status | Reason |
| --- | --- | --- |
| Install the declared environment | Partial | Conda fixes Python at 3.10, but dependencies use lower bounds rather than a lockfile. |
| Inspect maintained source | Yes | The modular Python implementation is tracked under `src/`. |
| Run focused offline tests | Yes | Tests cover distance branching/cache behavior, graph edge cases, deterministic approximations, weighted means, and connector-sentinel handling. |

## Environment setup

The supported environment target is Python 3.10. Conda is the most specific setup currently declared:

```bash
conda env create -f environment.yml
conda activate ev-charging-optimization
```

Alternatively, create a Python 3.10 virtual environment:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Neither environment file records exact transitive versions, platform details, or solver output. A newly resolved environment may therefore differ from the historical one.

Focused public-edition checks can be run with:

```bash
python -m pip install pytest ruff
ruff format --check .
ruff check .
pytest -q
```

GitHub Actions runs the same formatting, lint, and test checks on Python 3.10. CI does not download research data, contact OSRM, deserialize historical models, or execute the thesis pipeline.

The expected historical registry is described in [Data Documentation](DATA.md), but the exact November 2022 file is absent. A current download is a different snapshot and should not be presented as reproducing the thesis. Before execution, record the canonical URL, acquisition timestamp, provider release, governing terms, and SHA-256 checksum.

## Implemented command paths

These commands document the available code paths. They are not a promise that newly acquired data will reproduce the archived outputs.

```bash
python -m src.preprocessing
python -m src.statistics
python -m src.network --year-range 2009 2022
python -m src.analysis --years 2009 2010 2011 2012 2013 2014 2015 2016 2017 2018 2019 2020 2021 2022
python -m src.prediction
python -m src.optimization --year 2011 --num-stations 174
python -m src.visualization --years 2012
```

`python main.py` runs preprocessing, statistics, network generation, analysis, and prediction when no `--step` is supplied. It does **not** run optimization or visualization automatically. Use `python main.py --help` to inspect the CLI before starting a data-dependent stage.

Important execution constraints:

- Network construction considers every station pair for each cumulative year, producing quadratic growth in distance checks.
- Pairs inside the 100 km Haversine prefilter are sent to `https://router.project-osrm.org`; successful distances are cached in `distances.db`.
- The [OSRM demo policy](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server) limits clients to reasonable non-commercial use and at most one request per second. The current builder has no throttle, so a full run should use a self-hosted, versioned OSRM instance.
- Failed OSRM requests return no distance and cause the corresponding graph edge to be omitted. A future run must record request failures and define a deliberate fallback policy.
- Several stages display Matplotlib figures interactively and may require a suitable backend.
- The 2026 tests validate the corrected distance-unit branch; the historical graphs and optimization artifacts were not regenerated.

## Requirements for a complete reproduction package

A future archival release would need, subject to data rights:

1. Exact input URLs, acquisition dates, versions, terms, and checksums.
2. A privacy-reviewed redistributable snapshot or deterministic acquisition procedure plus a licensed test fixture.
3. A dependency lock for every supported platform.
4. A self-hosted OSRM version, routing profile, OpenStreetMap extract date, and cache checksum.
5. Explicit seeds for Python, NumPy, scikit-learn, NetworkX, and every genetic-algorithm trial.
6. Rebuilt GraphML and result artifacts using the corrected distance semantics.
7. Multiple independent optimization runs plus random, greedy, and facility-location baselines.
8. A structured experiment configuration and machine-readable mapping from each result to its data, code, environment, seed, and parameters.
9. A small licensed fixture that exercises the complete pipeline in CI without external network calls.
