# Data Documentation

## Overview

The project uses two geospatial inputs:

1. A charging-station registry attributed in the 2023 thesis to the German Federal Network Agency, the Bundesnetzagentur.
2. A GeoJSON file containing the boundaries of Germany's 16 federal states.

The raw and processed charging-station CSV files are not tracked. The boundary file is tracked without embedded provenance. A strong upstream match for that file is documented below, but the relationship was reconstructed for this public edition rather than recorded with the original experiment.

Unknown provenance fields are recorded explicitly rather than filled with inference.

The thesis describes fields for the operator, address, city, federal state, latitude, longitude, commissioning date, connector type and count, and delivered power. The preprocessing code expects a semicolon-delimited, Latin-1 CSV with ten non-data lines before the header.

### Repository handling

`src/preprocessing.py` performs the following operations:

- Renames selected German headers to English.
- Maps normal and fast charger labels to `normal` and `fast`.
- Preserves missing secondary connector types and fills missing secondary power values with `0`.
- Removes public-key columns.
- Converts decimal commas to decimal points for geographic and power columns.
- Parses commissioning dates in `DD.MM.YYYY` format.
- Trims text values, normalizes selected city names, and removes duplicate rows.
- Writes `data/processed/ChargingStationCleaned.csv`.

Both the raw and processed CSV patterns are ignored by Git. This avoids redistributing an exact November 2022 snapshot whose acquisition record and attached terms were not preserved, but it prevents a clean-clone reproduction. The current official dataset has documented CC BY 4.0 terms; those current terms do not by themselves establish the provenance of the absent historical file.

### Data-quality cautions

- The historical connector workbook was generated by legacy preprocessing that filled missing connector types with `0`; the maintained code corrects this, but the workbook was not regenerated.
- Only a small, hard-coded set of city and encoding corrections is applied.
- Duplicate removal is row-wide and does not define a stable station identifier.
- The code does not record rejected rows, missing-coordinate rates, or before/after row counts in a persistent quality report.
- The original snapshot is absent, so the processed values cannot currently be audited against the provider data.

### Required action before redistribution

Locate the exact historical release or a documented replacement from the official provider. Record the canonical landing page and download URL, release date, checksum, license or terms, and required attribution. The current official page states that the register data is licensed under CC BY 4.0 and requests attribution to `Bundesnetzagentur.de`; preserve an archived copy of those terms with any future snapshot. If a particular release cannot be redistributed, publish an acquisition procedure and a small synthetic or explicitly licensed test fixture instead of the original file.

The local file contains state names and identifiers such as `DE-BW`, `DE-BY`, and `DE-BE`, but no source, copyright, license, CRS, or attribution metadata. The archived upstream repository exposes a file with the same distinctive path, 70-line structure, approximate size, schema, and inspected coordinate content. This is strong evidence of origin, but the local history does not contain an acquisition record or upstream checksum.

### Boundary attribution

Use the following conservative attribution while retaining the provenance caveat:

> Germany federal-state boundaries from [deutschlandGeoJSON](https://github.com/isellsoap/deutschlandGeoJSON) by `isellsoap`, low-resolution federal-states file, repository released under [The Unlicense](https://github.com/isellsoap/deutschlandGeoJSON/blob/main/LICENSE.md). The upstream project credits `GIS-DATA` as its source.

Because the upstream README credits another data source without a precise dataset URL or source-license statement, verify that upstream chain before relying on the repository-level Unlicense for a formal data release. If that chain cannot be established, replace the boundary file with a dataset whose origin, version, license, and required attribution are explicit.

## Routing-derived distances

The source code can query the public OSRM demonstration endpoint at `router.project-osrm.org` over HTTPS and cache returned distances in `distances.db`. The thesis states that OSRM uses OpenStreetMap data. No OSRM response, service version, routing profile version, or OpenStreetMap extract date is recorded with the historical outputs. The 2026 portfolio code corrects the original distance-unit prefilter, but no historical result was regenerated.

The [OSRM demo-server policy](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server) limits use to reasonable non-commercial cases, asks clients not to exceed one request per second, and provides no uptime, latency, or data-update guarantee. The current graph builder does not throttle its quadratic request loop, so a complete run should use a self-hosted, versioned OSRM instance rather than the public demo service. Failed requests currently return no distance and therefore omit the corresponding edge.

Any future run should record the routing service or self-hosted image version, profile, underlying OpenStreetMap extract date, request failures, fallback policy, and cache checksum. When OpenStreetMap-derived material is published, verify and apply the current attribution requirements at <https://www.openstreetmap.org/copyright>.

## Suggested source manifest

For each external input, record at least:

```yaml
name: ""
provider: ""
landing_page: ""
download_url: ""
downloaded_at_utc: ""
release_or_snapshot: ""
sha256: ""
license_or_terms_url: ""
required_attribution: ""
local_path: ""
transformations: []
```

An empty field is not evidence. Resolve every field before describing the dataset as reproducible or cleared for redistribution.
